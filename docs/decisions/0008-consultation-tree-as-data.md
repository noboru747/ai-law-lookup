# 0008 問診樹寫成資料（data/tree.json），slot 以確定性規則影響結果

- 狀態：已採納
- 日期：2026-10-31

## 背景

spec 5 要求問診樹是資料而不是程式；樹本身就是範圍宣告。降級版沒有模型，因此使用者在表單填的事實，必須用確定性規則影響結果，而不是只被記錄下來。

## 決定

### 檔案與節點

`data/tree.json`（JSON，而非 YAML，避免多一個建置依賴），前端在 build 時匯入。節點分兩種：

- 選單節點（有 `children`）：只有 `id`、`label`、`description`。深度為根 → 情境分類 → 葉節點，共 3 層，以生活情境分類，不使用法律名稱。
- 葉節點：`type` 為 `query`／`process`／`out_of_scope`，另外擴充了 `freeform`（「其他」分支）。`answer_kind`（rule／exception／process）對應 spec 5.2 的三種回答類型。

葉節點的檢索欄位（spec 5.1 之外的擴充）：

- `law_scope`：`[{doc, part?, section?, chapter?, ids?}]`，用 `doc_id` 與條文 metadata 做確定性過濾，不使用法規中文名稱字串比對。
- `query`：BM25 用的查詢詞，由作者用條文用語撰寫（把「退貨」對映成「解除契約、退回商品、收受商品」）。
- `seed`：永遠列出的核心條文；`top_k`：BM25 補充幾條。
- `slots`、`rules`、`steps`（流程型）、`caveat_ref`（行業別公告的「取決於契約」提醒）。
- 共用的 slot 與規則組放在 `defs`，以 `{"$ref": ...}` 引用（網購退貨與例外商品共用商品類型與告知規則）。

### slot 與規則

- slot 型別：`select`、`date`。`show_if` 讓欄位只在會影響答案時才出現（「是否拆封」只在影音商品／衛生用品出現）；被隱藏欄位的舊答案會被丟棄，不會觸發規則。
- 規則：`when`（各 slot 間 AND、同一 slot 的多個值 OR）→ `pin`（把條文排到最前，可帶 `mark` 高亮條文中的原文片段，`background: true` 表示放在核心條文之後）、`add_query`（補查詢詞）、`note`（只指向條文用語的提示）。
- 結果順序：規則釘選 → seed → background 釘選 → BM25 補充 → 被引用帶出。
- 日期欄位只產生中性的衍生事實（「距今 N 日；條文所載期間為七日；本系統不判斷是否逾期」），不做逾期結論。
- 所有 `note` 與 `mark` 都只能指向條文原文用語，不下結論；測試會檢查每個 `mark` 都是被引用條文的逐字子字串，並檢查每條規則都能觸發。
- 流程型葉節點用 `steps`（有順序的步驟，各掛條文），`current_when` 依「目前進度」標示使用者可能在哪一步。

### 範圍外與其他

- `out_of_scope` 葉節點：顯示固定模板、列出可能相關但未收錄的法規名稱（不附條文、不附連結）、轉介提示。轉介目前是 `templates.referral` 的固定文字，Phase 4 改查表。
- `freeform`：不問診，在全庫做 BM25，頁面固定標示「未經問診，結果僅供參考」。Phase 3 會改由模型重新導向。

## 代價

- 規則要人工寫，每新增葉節點就要查條文、寫規則、寫測試；這是刻意的：範圍與判斷邏輯都在資料裡，可以逐條審查。
- `seed` 與 `pin` 讓結果比純 BM25 好，但也代表「撈得到」不能全算檢索的功勞。測試因此分兩層：只用 `law_scope + query` 的 BM25 排名，以及含規則的完整結果，Phase 5 評測也要分開量測。
- 流程型葉節點的 BM25 本身撈不到多數流程條文（申請調解、調解後、訴訟），完全靠 `steps`；這是已知限制，不是遺漏。
