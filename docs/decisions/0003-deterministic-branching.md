# 0003 分支由程式決定，模型只生成文字、不下結論

- 狀態：已採納
- 日期：2026-10-31

## 背景

法律資訊領域的錯誤成本高。模型擅長語意理解與文字整理，但不擅長穩定地遵守範圍邊界，也可能產生看似合理卻無依據的結論。專案要展示的正是「確定性流程與模型生成的分工」。

## 考慮過的選項

1. 全部交給模型：使用者自由輸入，模型自行判斷法規並回答。
2. 問診樹由程式決定分支，模型僅在最後一步依檢索到的條文生成說明。
3. 完全不用模型，只做條文查詢。

## 決定

採選項 2：

- 問診樹以 JSON/YAML 資料定義，分支、`law_scope`、必要欄位（slots）皆由程式決定；唯一例外是「其他」→ 自由輸入時，由模型協助重新導向到既有分支。
- 檢索範圍由節點的 `law_scope` 做確定性 metadata 過濾。
- 生成層只做「條文要件 × 使用者事實 → 附引用的說明」，不負責下結論；涉及見解分歧或取決於契約內容時，須明確標示。
- **沒有檢索到範圍內的條文，就不呼叫模型。**範圍外一律使用模板回覆。
- 每個回答必須附條號與原文；找不到依據時明確拒答。

## 代價/後果

- 使用者體驗較不「聰明」，只能走樹上有的分支；樹的維護成本由人工承擔。
- 生成層可拔除，系統在無模型時仍可運作（見 ADR 0004）。
- 行為可被評測：該回答／該追問／該拒答／該轉介，都能以葉節點為單位量測。
