# 0004 方案 C：靜態前端 + 前端 BM25 + 可降級的家用 Ollama 生成

- 狀態：已採納
- 日期：2026-10-31

## 背景

作品集專案需要在面試時穩定展示，但生成層依賴家用電腦上的 Ollama，可用性無法保證。同時專案預算與維運力有限，不宜維運正式的後端與資料庫。

## 考慮過的選項

- 方案 A：完整後端（API + DB + 向量檢索 + 生成）部署於雲端。成本與維運重，且 GPU 推論在雲端昂貴。
- 方案 B：全部放在家用電腦，前端也由家用電腦提供。家用電腦離線時整個系統不可用。
- 方案 C：Cloudflare Pages 靜態前端；問診樹與檢索（預建索引，例如 MiniSearch／BM25）都在瀏覽器執行；僅生成層經 Cloudflare Tunnel 連到家用 Ollama，且可拔除。

## 決定

採方案 C。

- 頁面載入時先打 health check，介面標示「完整版」或「降級版」。
- 生成 API 遇到任何非 2xx、網路錯誤或逾時（15 秒）即切換到降級模式。
- 降級模式顯示：問診結果 + 相關條文原文 + 轉介資源，只少生成層。
- Phase 1 先採前端 BM25 + metadata 過濾（問診樹已把範圍收窄）；是否在後端加入向量檢索做混合檢索，待 Phase 3 之後評估。
- 另錄製 Demo 影片，避免面試時後端離線。

## 代價/後果

- 預建索引需隨法規快照一起發佈，索引大小受瀏覽器載入限制。
- 前端 BM25 對語意相近但用詞不同的查詢召回較弱，需靠問診樹縮小範圍補償。
- 免費且高可用的展示面，但完整版體驗取決於家用電腦與 Tunnel 是否在線。
