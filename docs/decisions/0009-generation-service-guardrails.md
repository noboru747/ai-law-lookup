# 0009 生成服務的護欄：伺服器讀原文、引用驗證、無條文不生成

- 狀態：已採納
- 日期：2026-10-31

## 背景

ADR 0003／0004 決定生成層只做「條文 × 使用者事實 → 附引用的說明」，且可拔除。Phase 3 在家用電腦上實作該服務（`server/`），經 Cloudflare Tunnel 對外。它是公開端點，輸入不可信；輸出若含錯誤條號或個案結論，在法律資訊領域成本很高。護欄必須由程式強制，不能只靠 prompt。

## 決定

### 1. 條文原文由伺服器自行讀取
`POST /generate` 只接受 `article_ids`，伺服器從 `data/laws/*.json` 取原文組 prompt；請求中任何其他欄位（例如夾帶的條文文字）一律忽略。效果：原文來源唯一、前端或第三方無法注入假條文。未知 id、已刪除（`deleted`）條文回 400。

### 2. 沒有條文就不生成
`article_ids` 為空回 422，不呼叫模型（落實 ADR 0003）。`out_of_scope` 葉節點與未知葉節點回 400。

### 3. 結構化輸出 + 伺服器端驗證，不合格重試一次，再失敗回 502
以 Ollama `format` 傳入 JSON Schema（`citations` 的 enum 限定為本次提供的 id）。模型輸出後，伺服器再驗證：
- `citations` ⊆ 提供的 `article_ids`；
- answer 內的 `[id]` 標註 ⊆ 提供的 id；
- answer 內出現的「第N條／第N點」必須是提供條文自身的條號，或提供條文原文內本來就提到的條號（擋掉憑印象補充的條號）；
- 不含「你一定」「已違法」等對個案下結論的用語（簡單詞表，僅為輔助，不是完整防線）。

失敗時帶著剩餘時間預算重試一次；仍失敗回 502，前端依 ADR 0004 降級顯示原文。已知限制：條號比對不分法規（本法與施行細則同號時無法區分），語意層面的錯誤（例如把條文要件說錯）無法由程式驗出，仍靠 prompt、原文並列顯示與評測處理。

### 4. Prompt 規則
只依提供條文；每個論點附 `[id]`；用「條文規定…」「若…則條文所載…」句型；取決於契約或資訊不足寫進 `caveats`；不提供法律意見。使用者文字（query、slot 值）放在 `<user_facts>`／`<user_query>` 區塊，宣告為資料不是指令，並將其中的 `<` `>` 轉為全形以免關閉標籤。slot 只接受葉節點定義過的 key，並用 tree.json 的選項文字呈現（不送內部代碼）。

### 5. 模型：qwen3:14b，關閉思考
- 選 qwen3:14b：中文能力、指令遵循與 JSON 格式穩定度適合這類「受限改寫」任務；14B 在 RTX 5080 16GB 可常駐，實測單次 2–4 秒。
- 不用 Rocinante-12B：它是創作／角色扮演微調，傾向發揮與延伸，與「嚴格受限於提供條文」的目標相反。qwen2.5:7b 較小，保留不動。
- 以 API 參數 `think:false` 關閉思考（比在 prompt 加 `/no_think` 可靠），並在伺服器端若偵測到 `<think>` 標籤即視為失敗。`temperature=0`。
- 啟動時預熱模型（避免冷啟動超過 15 秒預算）。

### 6. 公開端點的防護
只開 `/health`、`/rewrite`、`/route`、`/generate`（無 docs／openapi）；只綁 127.0.0.1；body 大小上限、query／slot 長度上限；每 IP 簡單 rate limit（在 tunnel 後讀 `CF-Connecting-IP`，且僅在連線來自 loopback 時採信）；CORS 白名單（localhost:5173、localhost:4173、`https://*.pages.dev`）；單次請求總預算 14 秒，並限制同時推論數以保護 GPU。所有閾值以環境變數調整（見 `server/README.md`）。

### 7. 檢索輔助端點同樣受限
`/rewrite` 只輸出關鍵詞，伺服器過濾條號形式的詞；`/route` 的輸出以候選葉節點 id 為 enum 並再驗證，不在候選內一律回 `null`。兩者都不產生對使用者的結論。

### 8. 回應結構化：summary/points，為了可讀性與逐點可追溯
單一段落的 `answer` 對使用者太長、太雜，也無法看出哪句話出自哪一條。`/generate` 改為要求模型輸出 `summary`（一句白話重點，≤60 字，須以「條文規定」「依規定」開頭）、`points`（2–4 條，每條 ≤50 字，各自帶 `citations`）、`caveats`（≤2 條，各 ≤40 字），仍以 Ollama `format` JSON Schema 約束。向下相容：回應保留 `answer`（由伺服器把 points 串成每行一點並附 `[id]`，不再由模型產生）與 `citations`（所有 points 引用的聯集）。

驗證擴充：每個 point 的 citations ⊆ 送出的 article_ids 且至少 1 個；summary／points 不得為空；超過字數上限 1.5 倍視為過長；summary 與 points 文字不得出現條號 id 字串；條號比對與結論用語檢查改套用到 summary 與每個 point。失敗重試一次，再失敗 502。因 temperature=0 下原樣重試只會得到相同輸出，重試時改為附上被拒原因並將 temperature 提高到 0.3。

Prompt 收緊：不得直接對使用者下判斷，禁用「你可以」「可無條件」「一定可以」等，改用「條文規定消費者得…」。已知限制：詞表只擋明顯斷言，模型仍可能以第三人稱敘述（「消費者可在七日內退貨」），語氣是否過度仍需評測把關。

## 代價/後果

- 驗證偏嚴，偶爾會因模型多寫一個條號而重試，延遲增加；失敗時前端降級，使用者仍看得到原文。
- 條號驗證是啟發式，不能取代人工評測；Phase 5 的評測應納入「引用正確性」與「是否越界下結論」。
- 服務依賴家用電腦、Ollama 與 Tunnel 同時在線；離線即降級，符合 ADR 0004。
