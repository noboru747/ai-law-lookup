# 0001 刻意排除的範圍

- 狀態：已採納
- 日期：2026-10-31

## 背景

系統定位為「法規資訊查詢」，目標是展示範圍控制與 AI 應用邊界，而不是做完整的法律產品。法律領域一旦範圍失控，就會同時面臨高風險回答、資料量爆炸與見解分歧三個問題。

## 考慮過的選項

1. 盡量廣泛收錄，用免責聲明降低風險。
2. 只收錄消費糾紛核心，其餘領域明確排除，並在目錄層辨識後轉介。

## 決定

採選項 2。刻意排除：

| 排除項目 | 理由 |
|---|---|
| 刑法 | 高風險，且不屬於消費糾紛 |
| 勞基法 | 高度依賴主管機關解釋、涉及計算、行政機關與法院見解分歧 |
| 稅務 | 計算型問題，需要年度參數表與計算引擎，是另一套系統 |
| 交通 | 原本的候選領域，為收斂 MVP 範圍而暫緩 |
| 判決書 | 量大、格式雜亂、見解分歧 |
| 函釋全集 | 範圍會爆炸；必要時以主管機關官方說明頁補充 |
| 緊急應對（失火、自傷等） | 不在設計目標內，統一使用非法律模板回覆 |

被排除或不在收錄範圍的問題，由「目錄層」辨識並轉介，而不是沉默或硬答。

## 代價/後果

- 可回答的問題變少，使用者可能遇到「不在範圍」的回覆。
- 換來可驗證的邊界：問診樹上有的分支即支援範圍，評測集可以明確分「範圍內／範圍外／跨範圍」。
- 緊急狀況不處理，正式產品需另行設計安全機制，須在 README 已知限制中載明。
