# 0010 口語查詢：先用同義詞表 + LLM 改寫，暫不做向量檢索

- 狀態：已採納（向量檢索留待 Phase 5 數據決定）
- 日期：2026-11-01

## 背景

ADR 0007 的煙霧測試顯示，BM25（字元 bigram）最大的弱點是**詞彙落差**：使用者說「鑑賞期」「內衣褲」「倒閉」「電商」「7天」，條文寫「解除權」「個人衛生用品」「歇業」「通訊交易」「七日」，兩邊沒有共同的 bigram。ADR 0004 把「是否加向量檢索」留到 Phase 3 之後。Phase 3 有了生成服務（ADR 0009），多了一個可用的 LLM，但它隨時可能不在線（ADR 0004）。

## 考慮過的選項

1. **向量檢索（embedding）**：能補語意落差，但要建索引、挑模型、前端或後端多一條路徑，降級版（沒有後端）用不上；而且目前沒有隔離的評測集，無法證明它比下面兩層多贏多少。
2. **只靠 LLM 改寫**：口語 → 條文用語。實測不可靠（見下），而且降級時完全失效。
3. **確定性同義詞表 + LLM 改寫（採用）**：兩層都只是「在 BM25 查詢後面追加詞」，檢索與排序本身不變，結果仍是原文。

## 決定

查詢經過兩層展開，再交給同一個 BM25（`web/src/lib/glossary.js` 的 `planQuery`）：

1. **同義詞表（確定性，永遠開啟）**：`data/glossary.json`，每條 `from`（口語別名）→ `to`（法條用語）＋ `note`。另有程式內建的數字規則：`7天`／`七天` → `七日`、`30%` → `百分之三十`、`3倍` → `三倍`（條文用中文數字、以「日」計）。只追加詞，不刪使用者原文。`to` 的每個詞都必須真的出現在收錄條文（`glossary.test.js` 檢查），避免表與語料脫節。
2. **LLM 改寫（完整版才有）**：`POST /rewrite` 回傳關鍵詞，經清理（只收字串、去重、最多 12 個、每個 20 字內）後與同義詞合併。只有「其他」自由輸入會呼叫（問診樹葉節點的 `query` 由作者以條文用語寫成，本來就沒有口語輸入）。
3. 介面可展開「實際用來檢索的詞」，逐項列出：原文、同義詞命中（含別名與註記）、AI 改寫詞、最後送進 BM25 的字串、檢索範圍。

### 降級時的行為

| 情況 | 行為 |
|---|---|
| 降級版（health 失敗或未設 `VITE_API_URL`） | 不碰網路；只用同義詞表 + BM25；追溯面板標示「AI 改寫：未使用（降級版）」 |
| 完整版但 `/rewrite` 失敗、逾時、格式不符 | 只用同義詞表；追溯面板標示原因 |
| 完整版但 `/route` 失敗或信心 low／null | 在全部條文中檢索（Phase 2 行為），並提示原因 |
| `/route` 回傳不存在或不可導向的節點（含 `other`） | 視為 low，忽略 |
| `/generate` 失敗、逾時、citations 不在本次送出的 article_ids | 不顯示回答，只顯示原文，並標示原因 |

因此同義詞表是**保底層**，LLM 只是加分；兩者任何一個缺席，都不會讓頁面壞掉。

## 數字（開發用煙霧測試，不是評測）

同一批 20 句口語查詢（ADR 0007 使用的那批，全庫檢索，`web/test/smoke-queries.js`），unigram 權重 0.25：

| | MRR | hit@5 | hit@10 |
|---|---|---|---|
| 只有 BM25（Phase 2） | 0.468 | 12/20 | 14/20 |
| + 同義詞表 | 0.818 | 20/20 | 20/20 |

**這個提升不能當作泛化能力的證據。** 這 20 句同時是 ADR 0007 的調參資料，也是我決定同義詞表要收哪些詞的依據（「鑑賞期」「內衣褲」「倒閉」「電商」「7天」「線上課程」「轉讓」「幾天內」等條目就是從失敗的查詢來的）。我盡量把每條寫成一般性對映（有別名群、並附註記，也收了與這批題目無關的常見口語，例如投訴、打官司、霸王條款、不可抗力），但表的內容與這批題目的重疊程度無法被這批題目自己驗證。Phase 5 必須用另一批隔離、事先凍結、不參與詞表設計的題目，才能回答「詞表在沒看過的口語上有多少效果」。

## LLM 改寫的實際表現

後端實測（卡比獸回報）：「買生鮮食品不能退貨」的 `/rewrite` 沒有產出「易於腐敗」。這正是同義詞表存在的理由：口語到條文用語的**關鍵詞**對映，LLM 並不比人工表可靠，特別是法律冷僻用語。改寫目前的價值在於補充詞表沒收的說法（例如在本機實測，改寫會補出「食品退貨例外」之類的詞），但這些詞偶爾偏題；它們都會顯示在追溯面板，使用者與審查者看得到。

## 為什麼暫不做向量檢索

- 尚無隔離評測集，沒有數據能說明剩下的失敗是詞彙落差還是別的原因。
- 兩層擴展都是可追溯的字串；向量檢索的命中原因不可解釋，與本專案「結果必須能對照原文與來源」的方向不一致。
- 降級版無法使用向量檢索（需要模型或預先建好並載入的索引）。
- 重新評估的條件：Phase 5 用隔離題目量測 BM25 + 同義詞 + 改寫的 hit@10，若仍有明顯的詞彙落差失敗，再比較「加向量混合檢索」的增益與成本。

## 代價 / 後續

- 詞表需要人工維護，漏掉的說法仍然撈不到；加詞是便宜的，但過度擴展會稀釋 BM25（例如「店家」→「企業經營者」這種每條都出現的詞，IDF 低，影響小但不是零）。
- 子字串比對可能誤觸（例如較短的別名出現在不相關的句子裡）；所以別名都盡量取 2 字以上的詞，且只追加詞、不刪原文，誤觸的代價是少量雜訊而非漏檢。
- 展開後的查詢比較長，BM25 分數不可跨查詢比較（同 ADR 0007）。
